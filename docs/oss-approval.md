# Open-source approval record

The repository stays private until legal and security approval is recorded in the internal tracking issue. Changing visibility to public before that is a policy violation. This page is the checklist the reviewers fill in; the signed-off copy lives in the issue, not here.

**Approved commit SHA:** `________` (any later commit needs a re-check before the flip)

## Legal

- [ ] License: MIT, `LICENSE` present, copyright holder correct.
- [ ] `THIRD_PARTY_NOTICES` generated by `scripts/make-notices.mjs` and reviewed; every production dependency license is on the allowlist (MIT, ISC, Apache-2.0, BSD-2/3-Clause, 0BSD, MPL-2.0, BlueOak-1.0.0, Python-2.0, CC0-1.0).
- [ ] The binaries bundle the Node.js runtime: its `LICENSE` ships beside the binary as `NODE_LICENSE`, and the reviewers accept Node.js's aggregated third-party notices.
- [ ] No customer data, internal hostnames, internal ticket links, or non-public product names in the repository, docs, tests or fixtures.
- [ ] Trademark and branding use of "HG Insights" acceptable.
- [ ] Data-handling statement: `hgi` sends requests only to the configured server, stores tokens locally, and has no telemetry (`docs/security.md`, README).

## Security

- [ ] `SECURITY.md` present; private vulnerability reporting will be enabled by `scripts/configure-repo-security.sh`.
- [ ] Secret scan of **all refs** clean: `gitleaks git --log-opts="--all"`; plus Actions run logs, uploaded artifacts, and PR / issue / review comment threads reviewed by a person and old runs deleted.
- [ ] `docs/security.md` risk acceptance (30-day refresh token in a `0600` file) reviewed and still accepted.
- [ ] SBOM reviewed; `npm audit --omit=dev` clean at the high level.
- [ ] Release pipeline reviewed ([releasing.md](releasing.md)): no secrets in the repository before the flip, `release` environment and tag ruleset applied at the flip.

## After the flip: prove the controls (paste results into the issue)

- [ ] A scratch branch with a **fake** secret was blocked by push protection or flagged by gitleaks. Use a syntactically valid, non-live GitHub token shape (`ghp_` followed by 36 random alphanumeric characters, generated at test time and never committed); documented example keys such as `AKIAIOSFODNN7EXAMPLE` are deliberately ignored by push protection and prove nothing. Record which control fired. Delete the branch afterwards.
- [ ] A direct push to `main` was rejected.
- [ ] A pull request without an approving review cannot be merged.
